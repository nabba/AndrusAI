# BotArmy — CrewAI Multi-Agent System

## Quick Reference
- Python 3.11+, CrewAI framework
- 5 agents: Commander, Researcher, Coder, Writer, Self-Improver
- LLM cascade (**OpenRouter + Ollama only** as of 2026-05-29): local Ollama → DeepSeek / MiniMax / Claude / Gemini, all via OpenRouter. The factory (`app/llm_factory.py`: `create_*_llm` for agents, `chat_completion_for_role` for raw calls) is the SOLE LLM access path — no direct Anthropic/OpenAI SDK use. The vision computer-use subsystem (`app/computer_use/` + `app/tools/computer_use_tool.py`) is the ONE documented native-Anthropic island (needs the `computer-use-2025-01-24` beta OpenRouter can't proxy); pinned by `tests/test_llm_factory_route_invariants.py::...test_no_anthropic_sdk_imports_outside_factory`.
- Memory stack: Mem0 + PostgreSQL/pgvector + Neo4j + ChromaDB RAG
- Phases A-E productionisation push (2026-05-22): single-source-of-truth runbook at `crewai-team/docs/PHASES_ABCDE_SUMMARY.md` — covers cost ceilings (Anthropic per-day cap, connector budgets), benchmark suite, code-intel v2 tools, reusable primitives (JsonlLedger / MasterSwitch / @switch_gated), and the executor CR-attribution / pre_classified_zone / governance_ratchet wiring. Default-OFF master switches throughout; `/budgets` Signal command + `/cp/settings` cards are the operator surfaces.

## Build & Run
- Memory stack: `docker compose up -d` (PostgreSQL, Neo4j, ChromaDB)
- Run agents (host-native dev): `python run_host.py` — or `docker compose up -d gateway` to run in-container
- Tests: `pytest tests/ -v`
- Install deps: `pip install -r requirements.txt`

## Operational Perimeter (post-2026-05 hardening pass)
- Gateway HTTP auth: `/api/cp/*` and `/epistemic/*` mutating routes require `Authorization: Bearer <gateway-secret>` when `GATEWAY_AUTH_REQUIRED=1`. Default ON in K8s, OFF on laptop dev. See `app/control_plane/auth_dep.py`.
- Internal Python callers bypass the dependency — auth boundary is HTTP, not function calls.
- NetworkPolicy egress allow-list enabled by default in K8s with permissive HTTPS-only seed; tighten by routing through an in-cluster proxy.
- Inbound DLQ: load-shed messages buffered (in-process deque or Redis list when `REDIS_DLQ_URL` set) and replayed by `dlq-drain` idle job.
- Three idle reconcilers keep memory stores convergent: `belief-outbox-neo4j` (Postgres→Neo4j), `belief-outbox-chroma` (Postgres→ChromaDB), `dlq-drain`.

- Self-healing pass (originally 2026-05-05; source restored 2026-05-07 — see PROGRAM.md §14): two opt-in subsystems. `TOOL_SUPERVISOR_ENABLED=1` wraps every CrewAI native-tool dispatch with classify→retry→substitute→soft-fail (`app/tool_runtime/supervisor.py`); `ERROR_RUNBOOKS_ENABLED=1` lets `error_monitor._record_anomaly` dispatch matched runbooks via `app/healing/runbooks.py:maybe_run_runbook` under 7 safety gates. Audit actors `tool_supervisor` and `self_heal_runbook`. Composes with — does not replace — the Recovery Loop.
- DB backup ownership (2026-05-16 split): ChromaDB stays gateway-owned via `app/healing/db_backup.py` (bind-mounted volume, no docker-exec needed). Postgres + Neo4j move to a host launchd LaunchAgent at `scripts/db_backup_host.plist` (daily 04:30 local) running `deploy/scripts/backup.sh` with `BACKUP_SKIP_CHROMADB=1`. Driver: the `tecnativa/docker-socket-proxy` denies `/exec/.../start` without the `EXEC: 1` flag (returns 403), and adding `EXEC: 1` would widen the gateway's blast radius. Neo4j Community's `neo4j-admin database dump` refuses online dumps, so the host script does `docker compose stop neo4j → dump in one-shot container → docker compose start neo4j` (~10–30 s downtime/run). Gateway short-circuits pg/neo4j when `DB_BACKUP_HOST_MANAGED=1` (default in compose) and records `skipped: True` placeholders; the freshness monitor in `app/healing/monitors/db_backup.py` does per-component staleness checks against non-skipped successes — a dead host LaunchAgent surfaces as `postgres=Nd, neo4j=Nd` rather than being masked by happy gateway-only chromadb runs. Operator install: `./scripts/install_db_backup.sh install`. See `crewai-team/docs/SELF_HEAL_V3.md` §12 and `crewai-team/deploy/RESTORE.md`.

## Architecture (read on demand — do NOT auto-load)
- Gateway boot HTTP-starvation fix (2026-05-29; PROGRAM §77; memory `project_gateway_boot_starvation_fix`): root-cause fix for the chronic "/health returns HTTP 000 for stretches right after boot, host watchdog restarts mid-job → boot-hang loop." The idle scheduler runs in a daemon thread *in the gateway process*, so CPU-bound idle work holds the GIL the asyncio event loop needs for `/health`. Two fixes in `app/idle_scheduler.py` (GATED): (1) moved the synchronous LLM `_refresh_catalog()` + `rehydrate_catalog(force=True)` out of `start()` (ran on the event-loop thread during lifespan) into `_run_boot_prep()` on the daemon thread — `start()` is now cheap; (2) defer MEDIUM/HEAVY jobs while `_in_warmup_phase()` (publishes `boot_warmup` deferral) + a GIL-yield sleep after each warm-up LIGHT job. **Out-of-process offload was deliberately rejected** — many idle jobs write the single-writer `chromadb.PersistentClient` KBs, so a second process reintroduces the §55 dual-writer corruption. 4 new fields in `app/config.py` (**TIER_IMMUTABLE, operator-approved**): `idle_boot_starvation_fix_enabled` (master, default ON; `IDLE_BOOT_STARVATION_FIX_ENABLED=0` reverts), `idle_warmup_defer_heavy`, `idle_warmup_defer_medium`, `idle_warmup_inter_job_pause_s`.
